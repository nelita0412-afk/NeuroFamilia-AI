# AGENTS.md

pnpm-workspaces monorepo for "NeuroFamilia AI" (a Spanish-language product). Four real members: `apps/api` (NestJS 11), `apps/web` (Next.js 16 App Router), `packages/database` (Prisma 7 + migrations, published as `@neurofamilia/database`), `packages/shared` (MIF mentor identity, published as `@neurofamilia/shared`). `packages/ai` is an empty placeholder. `MIGRATION.md` holds a detailed module/endpoint inventory and known risks — read it before touching auth, mentors, or mentor images.

## MIF mentor identity (single source of truth)
- `MENTOR_IDENTITY` and `MENTOR_NAMES` live in `packages/shared/src/mentors/` — types in `types.ts`, one file per mentor (`alba.ts`, `nia.ts`, …, `darwin.ts`), assembled in the `index.ts` barrel. Home, Archipiélago, Chat, and the API prompts all read from this one source — never duplicate mentor metadata elsewhere.
- `packages/shared` is the framework-agnostic shared domain of NeuroFamilia: no React, Next, NestJS, Prisma or UI-library dependencies. Every new shared domain (growth, families, …) should get its own `src/<domain>/` folder with a barrel, keeping `src/index.ts` as the public surface.
- Mentor identity is project IP: definitive content (personality, methodology, scientific content) is developed by phases — empty fields are structure ready to grow (`capabilities`, `competencies`, `scientificEvidence`, `resources`, `config` memory/personalization, …) without changing the architecture. Never invent content beyond what already exists.
- The API's `ScientificIntelligenceService` resolves each mentor's system prompt from `MENTOR_IDENTITY[name].basePrompt` (fallback ALBA). The old `prompts/*.prompt.ts` files no longer exist.
- `packages/shared` compiles to `dist` (CJS + d.ts). It must be built before `api`/`web` dev or build: root `pnpm dev` and `pnpm build` (topological) handle this; otherwise `pnpm --filter shared build`.
- Visual concerns live only in the web app: `lib/mentor-visuals.ts` maps mentor → lucide icon (`MENTOR_ICONS`) and color scheme (`MENTOR_COLORS`, `MentorColorScheme`). The web's `lib/mentor-identity.ts` is a thin re-export of the shared package (keep it that way) — it must not export `MENTOR_COLORS`/icons, which are UI concerns.

## Commands
- Install: `pnpm install` at root. Use pnpm only — never npm/yarn.
- Local infra: `docker compose up -d` — Postgres (pgvector) on host port **5433**, Redis on 6379. Required before `prisma migrate` or starting the API.
- Backend: `pnpm dev` (root, = `pnpm --filter shared build` + `pnpm --filter api start:dev`), port 3001. Note: root `dev` does NOT start the web app.
- Web: `pnpm --filter web dev`, port 3000.
- Prisma (must run from `packages/database`, where its `.env` lives): `pnpm generate`, `pnpm migrate`, `pnpm studio`.
- Build: `pnpm build` (all); individual: `pnpm --filter api build`, `pnpm --filter web build`.
- Lint: `pnpm --filter api lint` (note: runs with `--fix`), `pnpm --filter web lint`. No typecheck script anywhere.
- Tests: API only — `pnpm --filter api test`, `pnpm --filter api test:e2e`. The web app has no test setup.

## Setup gotchas
- All `.env` files are gitignored; nothing env-related is committed. The API hard-fails at boot without `DATABASE_URL`, `JWT_SECRET`, `GEMINI_API_KEY`, `GEMINI_MODEL` (`validateEnv` in `apps/api/src/config/env.validation.ts`). Create `apps/api/.env`, plus `packages/database/.env` for Prisma. `apps/web/.env.local` is optional (`NEXT_PUBLIC_API_BASE_URL`, default `http://localhost:3001`).
- Compose-valid `DATABASE_URL`: `postgresql://neurofamilia:neurofamilia@localhost:5433/neurofamilia`.
- The Prisma datasource has **no `url` field** — it is resolved from `process.env.DATABASE_URL` via `packages/database/prisma.config.ts`. Run `pnpm generate` after any schema change.
- `main.ts` enables CORS with `credentials: true`, so `CORS_ORIGIN` must be explicit origins (e.g. `http://localhost:3000`), never `*`.

## API contract quirks (verified, easy to get wrong)
- `/auth/login` returns `access_token` (snake_case), not `accessToken`.
- `/mentor/chat` DTO field is `mentor` (not `mentorName`); responses may contain Markdown the frontend normalizes in `normalizeMentorResponse` (`apps/web/src/app/(dashboard)/dashboard/mentores/page.tsx`).
- `relationship-permissions` has no controller/route — it is used only internally by `MentorModule`.
- Global guards: `ThrottlerGuard` → `JwtAuthGuard` → `RolesGuard` (`apps/api/src/app.module.ts`); public routes use `@Public()`.
- API has no URL version prefix and no `/api` path (e.g. `/families`, `/growth/profiles/:id/report`).

## Web app notes
- `apps/web/AGENTS.md` is **auto-regenerated by `next dev`** (Next 16 has breaking changes vs older docs — read `node_modules/next/dist/docs/` before writing Next.js code). Don't strip its block from commits; committing it keeps the tree clean.
- Next 16 + React 19: verify compatibility of any new dependency before installing.
- Mentor chat history is client-side only (`sessionStorage` key `neurofamilia_mentores_session_v1`), not persisted in the backend.
- The 8 mentors: `apps/web/src/lib/constants.ts` re-exports `MENTOR_NAMES` from the shared package; all identity data comes from `MENTOR_IDENTITY` in `packages/shared/src/mentors/`. Keep new mentor metadata there, not duplicated.
- Mentor PNGs in `public/images/mentores/*.png` are full posters with baked-in text/logo, cropped via CSS (`aspect-[9/16]` + `object-cover`); they are not transparent cutouts.
- `/auth/register` exists on the backend but there is no register page in the UI.
- UI copy and backend log messages are written in Spanish.
